# Architecture

Decision: a coherent local React/TypeScript UI, FastAPI API, Python subprocess worker and SQLite WAL database, reusing audited Chopify caption/timing/crop/smoothing primitives at 0d13b4a8ac8b91fd309cd54ffe8431bd3b13c5b6. This is a component reuse decision, not a claim that Chopify Unreleased is a stable application. Preserve MIT notice and document adaptations. FFmpeg/libass handles media/caption encoding instead of recreating a codec or caption renderer. Tiny Whisper and quantized MiniLM supply local speech/text inference. Pinned CLIP supplies still-frame retrieval; optional X-CLIP adds an experimental eight-frame temporal encoder, and PP-OCRv4 supplies visible-text detection/recognition using the existing NumPy/OpenCV/ONNX Runtime dependencies.

## Data and execution

Source copies are immutable. Separate directories hold sources, stage artifacts, proxies, transcript/analysis, separate OCR evidence and render packages. OCR never replaces transcript words or captions. Versioned timeline revisions reference one source and map ordered source-time ranges into output-time. Captions/crop keys retain source timestamps. Render jobs capture exact revision and source hash. Publications bind exact export fingerprint, and edits invalidate approval.

Render intermediates use PCM audio and explicit edit durations. A global CFR/AAC assembly prevents per-cut AAC priming/padding from accumulating against caption time. Caption burning preserves that assembled audio. Repeated-cut signal regression, a fixed 150ms duration ceiling and independent full decode validate this boundary. Encoding and revision-bound packaging are separate reusable stages.

SQLite transactions claim leases and globally bound heavy work. A worker supervisor heartbeats while isolated subprocesses do media/inference. Cancellation and lease loss terminate process groups. Stage fingerprints and atomic directory completion enable restart reuse; jobs execute at least once, with token fencing and idempotent outputs. HTTP acceptance is never render completion. UI and CLI call the same service methods. Heavy inference is sequential and CPU-only, with at most two inference threads: Whisper int8, MiniLM quantized, CLIP int8 text/uint8 vision, X-CLIP FP32 and PP-OCRv4 detector/recognizer graphs. Existing RAM/resource guards remain. No Redis/cloud database/paid service is introduced.

Loopback-only, host/origin validation, validated uploads, registered artifact paths, and a DNS-pinned HTTP fetcher protect local files/network. Publishing is a draft/manual handoff until a real authorized adapter is configured. Cloud and agent interfaces report capabilities honestly; no browser-subscription automation or unconfigured agent calls. Nonexecuting cloud preflight combines a server-observed source with declared price/budget assumptions; its pure evaluator never reserves budget or transmits. Publication preflight verifies current files and stored draft/approval but cannot post. Retention takes a bounded read-only snapshot and reports protected/review paths; there is no deletion/apply function.

Experimental X-CLIP retaining learned temporal attention is an architectural fact, not a quality result. Four paired reversal checks did not establish order recognition; CLIP remains the default. OCR sampling and geometric limits are likewise explicit. See the [OCR contract](OCR.md). Speaker diarization is not an integrated capability.
